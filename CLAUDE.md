# Foxconn Zhengzhou — interactive visualization site

MDE studio project (Rita Lyu & Eleanor Li). We are building the **Labor** page of a web visualization in `site/`.

## Read first
- Spec: `design/LABOR_STORYBOARD.md` — scenes, data, interactions, caveats, decisions. Follow it; if something is unclear or conflicts, ask instead of guessing.
- Reference images: `design/reference/`
- Folder map: `README.md`

## Data rules
- The site reads data **only** from `site/data/labor/*.json`. Never read the Excel/CSV files in `data/` or `outputs/` from site code.
- **Never hard-code a data value** (counts, shares, pay rates, years, FX rate). Read it from the JSON. If a value is missing, stop and say so.
- Placeholders (e.g. space per worker) must be labeled as placeholders on screen.
- Every chart shows its caveat text (from the JSON `caveat` field) in place.
- The JSON is generated by `scripts/export_site_data.py`. To change data, edit that script and re-run it from the project root (`python3 scripts/export_site_data.py`, using `.venv`); never hand-edit the JSON.

## Display rules
- **English only** for everything a viewer sees.
- **Money:** USD first, RMB in parentheses, e.g. `$3.73 (¥25)`. Use `fx_cny_per_usd` from `scene4_pay_model.json`; never show RMB alone.
- Private individuals are only ever "Individual". Never add names.
- Colors follow the worker type on every scene (see "Shared rules" in the storyboard). Red is only for the legal cap.
- Respect `prefers-reduced-motion`: every animation needs a static end state and a pause/skip control.

## Scope and workflow
- Work on **one scene or one transition per task**. Don't change other scenes.
- Don't edit `data/`, `outputs/`, `scripts/` (except `export_site_data.py` when asked), `docs/`, or `design/`.
- For bigger tasks, propose a short plan first and wait for approval.
- Stack: Vite + vanilla JS + D3 in `site/`. Ask before adding other libraries.
- After a task, tell me how to check it in the browser (which number or behavior to look for).
